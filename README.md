# Majestic Territory Capture

Серверная симуляция захвата территорий на Node.js и TypeScript. Время продвигается явным вызовом `tick()`, без таймеров и сетевого сервера.

## Запуск

Node.js 22.12+ или 24; разработка и проверка — на Node.js 24.

```sh
npm ci
npm run check
npm run demo
```

`check` запускает проверку типов, ESLint, проверку форматирования Prettier и тесты Vitest. Отдельно: `npm test`, `npm run typecheck`, `npm run lint`. Форматирование: `npm run format`.

Демо расставляет игроков, продвигает тики и проверяет прогресс, захват, оспаривание, защиту, доход и ручную смену владельца. Выводит состояния по этапам; при ошибке завершается с кодом 1. Тот же сценарий запускается тестами.

## Архитектура и API

- `TerritorySystem` — единственный публичный источник состояния зон и балансов. Сначала рассчитывает весь тик, затем фиксирует его и отправляет события. Ошибка расчёта не меняет время, зоны и балансы.
- `Zone` хранит состояние зоны и готовит следующий шаг. `CaptureRules` рассчитывает прогресс; `PeriodicIncome` — доход; `FactionLedger` проверяет и хранит балансы.
- Внешний `PlayerRegistry` реализует `IPlayerSource`: ядро читает и проверяет снимок игроков в начале тика. Демо и тесты управляют реестром, ядро от них не зависит.
- `EventBus` рассылает события после фиксации; каждый подписчик получает отдельную глубокую копию payload.

Публичные классы и типы экспортируются из `src/index.ts`. Пример ниже сохраните в `example.ts` в корне репозитория и запустите командой `npx tsx example.ts`:

```ts
import { TerritorySystem, PlayerRegistry } from './src/index.js';

const players = new PlayerRegistry();
const system = new TerritorySystem(
  {
    zones: [
      { id: 'alpha', center: { x: 0, y: 0 }, radius: 10, initialOwner: null },
    ],
  },
  players,
);

system.on('zoneCaptured', ({ zoneId, factionId }) =>
  console.log(zoneId, factionId),
);
players.upsert({ id: 'p1', factionId: 'blue', position: { x: 0, y: 0 } });
for (let i = 0; i < 10; i++) system.tick();
console.log(system.getZone('alpha'));
```

`getZones()` и `getZone(id)` возвращают копии (`null` для неизвестной зоны). `setOwner(id, factionId | null)` вручную меняет владельца; неизвестный id вызывает `UnknownZoneError`, а фракция, не являющаяся непустой строкой или `null`, — `TypeError`. Повторная установка того же владельца ничего не меняет. `getFactionScores()` возвращает копию балансов, `currentTick` — номер завершённого тика. `players.upsert()` добавляет игрока или меняет его фракцию/позицию; `remove()` возвращает `false`, если игрок уже отсутствует.

`on(event, handler)` возвращает функцию отписки. События: `zoneCaptured`, `ownerChanged`, `contestStarted`, `contestEnded`, `incomeGranted`. Порядок — зоны по конфигу, внутри зоны: оспаривание → захват → смена владельца → доход. Payload описывает переход, чтение API показывает итог всего тика.

Во время тика и рассылки `tick()` и `setOwner()` запрещены (`ReentrantCallError`). Реестр игроков менять можно: это повлияет на следующий тик. Ошибки подписчиков передаются в `onHandlerError` из опций конструктора (по умолчанию `console.error`) и не прерывают остальных; ошибка самого callback выводится в `console.error` без повторного вызова callback.

## Правила

Граница входит в зону: расстояние до центра ≤ радиуса. Игрок в пересечении учитывается в каждой зоне. Фракция — любая непустая строка.

| Присутствие                                    | Прогресс                                                       |
| ---------------------------------------------- | -------------------------------------------------------------- |
| Никого                                         | Уменьшается на `decayPerTick`; по умолчанию 0 — сохраняется    |
| Две и более фракции                            | Оспаривание, прогресс и захватчик заморожены                   |
| Только владелец                                | Сбивает полосу атакующего со скоростью по таблице              |
| Только атакующий с текущей полосой или без неё | Накапливает прогресс до порога                                 |
| Только другая чужая фракция                    | Сначала сбивает чужую полосу; свою начинает со следующего тика |

На нуле захватчик очищается. При снятии оспаривания правило оставшейся фракции применяется сразу. Выход, удаление и смена фракции игрока учитываются на следующем тике.

### Модель перехода владения

Выбран **прямой захват**: при достижении порога зона переходит от текущего владельца к атакующей фракции. Прогресс захвата сбрасывается. Отдельной игровой стадии нейтрализации нет.

#### Игровое обоснование

Модель даёт одинаковое время захвата нейтральной и чужой зоны при одинаковом числе атакующих и настройках. Одна полоса прогресса позволяет явно оценить, сколько осталось до смены владельца.

Защита обеспечивается присутствием владельца: пока в зоне есть несколько фракций, захват остановлен. Если защитники остаются одни, они постепенно сбивают накопленный атакующим прогресс. До завершения захвата текущий владелец продолжает получать доход.

Цена решения — чужая территория не требует дополнительного этапа захвата по сравнению с нейтральной. У защитников нет отдельного окна между потерей зоны и её получением противником; доход прекращается сразу при передаче владения. Для этой симуляции выбран более простой вариант с одним порогом. Модель с отдельной нейтрализацией подошла бы, если бы требовались более длительный перехват и период, когда доход не получает никто.

#### Техническое обоснование

Внутри передача выполняется через две операции: `release()` очищает контекст прежнего владельца, затем `assign()` устанавливает нового и начинает новый интервал дохода. Промежуточное отсутствие владельца не наблюдается через API: изменения фиксируются до рассылки событий.

Так очистка и инициализация сосредоточены в отдельных операциях, а накопленный интервал дохода прежнего владельца не переносится новому. Игровой захват и ручная смена через `setOwner()` используют тот же порядок.

При игровом захвате отправляются `zoneCaptured` и `ownerChanged` с причиной `capture`; при ручной смене — только `ownerChanged` с причиной `manual`.

### Доход

Доход получает фракция, непрерывно владевшая зоной весь тик. При захвате на тике T первая выплата — на T + `intervalTicks`; начальный владелец получает первую выплату на `intervalTicks`. Оспаривание и незавершённая атака доход не останавливают. Смена владельца сбрасывает интервал, неполный интервал теряется. Ручная смена сбрасывает полосу и отправляет только `ownerChanged` с причиной `manual`.

## Конфигурация и добавление зоны

Пример — `config/zones.json`. Для новой зоны достаточно добавить запись в `zones`, ядро менять не требуется. Поля `id`, `center`, `radius` и `initialOwner` обязательны; для нейтральной зоны явно укажите `initialOwner: null`:

```json
{
  "id": "gamma",
  "center": { "x": 100, "y": 20 },
  "radius": 12,
  "initialOwner": null,
  "capture": { "threshold": 200 },
  "income": { "amount": 20 }
}
```

Общие `defaults.capture` и `defaults.income` сливаются с полями зоны. Встроенные значения: `threshold: 100`, `gainByPlayers: [10, 15, 18]`, `decayPerTick: 0`, `amount: 5`, `intervalTicks: 10`. Таблица задаёт скорость для 1, 2, 3 игроков; все сверх длины получают последнюю скорость.

Порог и интервал — безопасные целые ≥ 1; скорости — непустая строго возрастающая таблица безопасных целых ≥ 1; затухание и доход — безопасные целые ≥ 0. Центры и позиции конечны, радиус конечен и положителен, id зон уникальны. Неизвестные ключи отклоняются; `ConfigValidationError` содержит путь поля. Переполнение баланса вызывает `ScoreOverflowError` до фиксации тика. Конфиг, игроки и результаты API не разделяют изменяемые ссылки с ядром.
